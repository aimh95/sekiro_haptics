# Claude Code: 최소 읽기 통합 계약

먼저 이 파일과 `preset_map.json`만 읽는다. `recipes.json`, `generate.py`, DESIGN.md, WAV 바이너리, docs/ 전체는 읽지 않는다. 파형은 이미 생성돼 있으므로 변경 요청이 없으면 재합성하지 않는다. AGENTS.md 등 필수 저장소 지침은 따른다.

## 범위

- 의수 10계열 + 돈 던지기/유리 수리검 변형. 22개 WAV는 48 kHz, IEEE float32, 논리 L/R 2채널 햅틱 자산이다. 4채널 장치의 어느 채널인지는 이 파일이 결정하지 않는다. 현재 확인된 라우팅을 사용한다.
- `preset_map.json`은 작성용 명세다. 기존 OutputPreset JSON과 동일한 형식이 아니다. 작은 변환/데이터 추가로 기존 스키마에 맞춰라. 새로운 범용 엔진/파형 DSL 파서를 만들지 마라.
- 기준 실행: `.\build-hw\apps\guard_feedback\sekiro_guard_feedback.exe --live --pid (Get-Process sekiro).Id --enemy`
- 기존 OutputRuntime/프리셋 로더/PCM Mixer/트리거 준비 상태 처리를 재사용한다. WAV 미지원이면 기존 디코더 지원을 먼저 확인하고, 필요한 최소 형식 지원만 추가한다. 데이터는 시작 시 로드한다.

## 이벤트와 트리거

- 맵의 requires는 필요한 의미를 설명한 이름이지, 저장소에 이미 존재한다고 보장하는 이벤트명이 아니다. 실제 소스에 맞춰 명시적으로 연결한다.
- 확인된 ID와 실제 사용/충돌 신호만 자동 연결한다. 현재 선택된 의수나 R2만으로 사용·명중·개별 베기를 만들지 않는다. 부족한 신호는 manual_only로 남긴다. 이번 작업에서 새 메모리 탐색을 벌이지 않는다.
- 공개/기존 카탈로그의 명시적 ID 대응만 사용한다. 숫자 범위로 계열을 추정하지 않는다. 미등록 ID는 unknown이다. 110000을 동전으로 단정하지 않는다. 강화형은 확인된 계열 기본 프리셋을 재사용하되, 미검증 단계/지속 기능을 자동 활성화하지 않는다.
- readyTrigger는 선택된 의수의 장착감이다. 사용 가능/사용 자원 잔량이 확인되지 않았다면 사용 가능하다는 보증으로 표시하지 않는다. 선택 변경/객체 변경/읽기 무효/종료 시 자신이 소유한 R2 효과를 정리한다. Weapon의 물리적 걸림 해제와 실제 게임 발사 이벤트는 별개다.
- selected 상태에서는 같은 트리거 효과를 매번 Reset/재전송하지 않는다. 현재 소유자와 효과 ID로 수명을 관리한다. 우산 deployed 신호가 검증돼 있을 때만 activeTrigger를 적용하고, 종료 후 현재 선택의 준비 효과로 복귀한다. 이전 효과의 만료가 새 효과를 끄면 안 된다.
- L2 와이어 동작을 유지한다. 패링/일반 방어 프리셋은 PCM만 교체하고 L2/R2를 점유하지 않는다.
- --enemy의 반응과 플레이어 자신의 방어 성공을 구분한다. 적 반응은 플레이어 실제 근접 공격이 원인일 때만 연결한다. 적끼리 전투/표창 반응 제외 조건을 유지한다. 일반 공격 명중을 blade_block으로 보내지 않는다.

## PCM 재생

- 기존 float 믹서에서 2채널 파형을 검증된 좌/우 햅틱 채널에 넣는다. 레거시 럼블 자동 대체 금지. PCM 경로가 없으면 미지원으로 표시한다. 트리거 전송으로 PCM 액추에이터 모드를 빼앗지 마라.
- 첫 비교 출력 게인은 0.6. 이는 파형 숫자의 배율이며 체감 60%가 아니다. 기존 추가 게인을 확인해 이중 배율을 피한다. 체감으로 전체 게인을 조정하되 개별 클립 자동 정규화는 하지 않는다.
- 단발은 서로 겹쳐 끝까지 재생한다. 개수로 전체 신호를 나누거나 새 이벤트마다 이전 커서를 리셋하지 않는다. 스피커 음원/볼륨/EQ/겹침 정책은 유지한다.
- loop는 검증된 지속 상태 동안 효과당 voice 하나를 유지하며 위상을 연속 재생한다. 1초마다 fade/재시작하지 않는다. 실제 진입 15ms/종료 35ms만 부드럽게 연결한다. 종료·사망·정보 무효 시 루프도 정리한다. 지속 상태가 없으면 루프는 수동 비교 전용이다.
- firecracker_use의 여러 봉우리는 한 사용 효과의 장식이다. 실제 개별 폭발/충돌 횟수를 뜻하지 않는다. sabimaru_cut/axe_impact/spear_pull/mist_raven_vanish 등은 각각 검증된 신호가 있어야 한다. 고정 타이머로 가짜 명중·베기·회피를 예약하지 않는다.
- sabimaru_use와 첫 cut처럼 같은 동작의 시작을 두 번 세게 강조할 수 있는 경로는 별도 확인한다. 지원 신호에 맞는 한 경로를 고르고 중복 출력을 만들지 않는다.
- 기존 리미터/헤드룸을 재사용한다. 좌/우의 동일한 제한 게인을 우선 검토하고 스피커는 별도로 처리한다. 이중 리미터나 새 오디오 엔진을 만들지 않는다.

## 검증과 보고

단발, 100/200/400ms 반복, 패링·방어 혼합, 의수 전환·unknown, 지속 루프 종료, L2/R2/스피커 동시 출력만 우선 확인한다. 필요한 회귀 테스트와 빌드를 실행하고 정상 로그는 파일로 남겨 요약만 출력한다. 토큰 절약을 이유로 필수 지침이나 검증을 생략하지 않는다.

완료 보고는 변경 파일, 검증 결과, live 지원/manual_only 표, 실제 존재하는 비교 명령만 짧게 적는다. 파일 생성/수학적 검증은 손맛 검증이 아니다. 이 묶음은 실제 칼 측정 데이터나 게임 추출 음원을 포함하지 않는다.
