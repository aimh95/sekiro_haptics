# 14. 햅틱 워크벤치 — 파형을 설계·재생·비교하는 GUI (2026-09-23)

문서 13의 단발 사인파 벤치를 **여러 레이어를 합성하는 편집기**로 키운 것이다.

```
python tools/haptic_lab_gui.py          # 저장소 루트에서
```

## 14.1 구조

| | |
|---|---|
| `src/lab/Expression.cpp` | 파형 수식 평가기. 허용된 함수만, 노드 수 상한 있음 |
| `src/lab/LayeredPreset.cpp` | 레이어 합성·분석·리미터 예측·FFT |
| `apps/haptic_lab/main.cpp` | 출력 프로세스. 장치를 한 번 열고 명령을 받는다 |
| `tools/haptic_lab_gui.py` | Tkinter 화면. 오디오를 전혀 소유하지 않는다 |

샘플 단위 처리는 전부 C++ 에 있고 GUI 는 설정과 관측만 한다. 기존 믹서, 연속 스트림,
다중 voice, 분리 리미터, HID 상태 단일 소유자를 그대로 재사용한다.

## 14.2 왜 레이어를 한 버퍼에 렌더하는가

각 레이어의 시작 시각과 시작 위상은 **프리셋 첫 샘플부터 센 샘플 수**다. GUI 타이머나
sleep, 또는 voice 를 따로 큐잉하는 방식은 Windows 스케줄러가 깨어나는 자리에 떨어진다 —
수십 ms 의 흔들림이고, 이 도구에서 비교할 간격보다 크다.

그래서 프리셋 전체를 한 스테레오 버퍼로 렌더해 **voice 한 쌍**으로 내보낸다. 첫 파형이
울리는 중에 두 번째가 시작하는 것은 산술이 되고, 새 레이어가 기존 레이어의 위상이나
잔향을 건드릴 방법이 구조적으로 없다. WAV 내보내기도 재생한 그 버퍼다.

검증: 30 ms 시작은 정확히 프레임 1440 이고(`LayeredPreset_ALayerStartsOnTheExactSample`),
레이어 2 를 추가해도 레이어 1 의 파형은 샘플 단위로 동일하다
(`LayeredPreset_ASecondLayerDoesNotResetTheFirstOnesPhase`).

## 14.3 수식 — 라디안이고, 분기가 나눗셈보다 먼저다

문법에 대입·반복·재귀가 없고 함수 목록이 고정되어 있다. 모르는 이름은 조회하지 않고
**거절**한다. 노드 상한이 있어 한 번의 평가 비용이 유한하다.

예제 두 개가 그대로 들어 있다:

```
A(t) = cos(2*t)*sin(460*t)
B(t) = if(t < t0, 0, cos(60*(t - t0))/t)
```

`if` 는 **단락 평가**다. 그래서 B 는 t < t0 구간에서 나눗셈을 아예 계산하지 않는다 —
t = 0 에서 분모가 0 이므로, 양쪽을 다 계산하는 평가기라면 무한대가 나와 합산 전체를
오염시킨다. 실측으로 `guardedDivisions = 0` 이 확인된다.

**460 을 Hz 라고 적지 않는다.** 괄호 안은 라디안이라 460 rad/s ≈ 73.2 Hz 다. 화면에도
그렇게 표시한다. 일반 주파수 입력칸은 Hz 이고 내부에서 2πft 로 바꾼다.

수식에 포락선·정규화·필터가 자동으로 붙지 않는다. t0/t, 지수 감쇠, 시작·종료 완화는
전부 따로 켜는 선택지이고, 켜져 있으면 분석 패널이 그 사실을 적는다.

B 는 t 가 t0 에 가까울 때 1/t 가 커져서 peak 가 15 를 넘기도 한다. 그것을 줄이지 않고
**그대로 보여준 뒤** 리미터가 얼마나 가져갔는지를 따로 적는다.

## 14.4 정규화하지 않는다

레이어별 자동 정규화도, A/B 마다의 자동 정규화도 없다. 저주파 단독과 저주파+고주파를
비교할 때 저주파가 그대로여야 비교가 성립하는데, 정규화하면 바로 그게 달라진다.
합은 부동소수점으로 더하고, 넘치면 넘친 채로 측정한 뒤 리미터 예측을 따로 보여준다.

`LayeredPreset_TheSumIsNotNormalised`, `LayeredPreset_OverRangeIsCountedNotClipped` 가
이걸 지킨다.

## 14.5 분석 화면이 말하는 것과 말하지 않는 것

보여주는 것: 레이어별 파형, 합산 결과, 리미터 **적용 전과 후**, peak, RMS,
평균값(DC), 범위 초과 샘플 수, 리미터 감쇄량과 동작 프레임 수, 최종 한계 초과 샘플 수.

FFT 는 길이·창 함수·분석 시작 샘플·분해능·채널을 항상 함께 표시하고, 단위를
**"PCM 진폭 (물리 단위 아님)"** 으로 명시한다. 창 함수의 coherent gain 을 나눠서
full-scale 사인파가 약 1.0 로 읽힌다. 구간이 신호 끝을 넘으면 0 으로 채우지 않고
**거절**한다 — 무음 반쪽의 스펙트럼을 신호의 스펙트럼인 양 보여주게 되기 때문이다.

보여주지 않는 것: 힘(N), 실제 이동거리, 손에 전달된 에너지. 이 프로세스에는 그걸 잴
수단이 없다. 내장 움직임 센서도 표본화 속도·대역폭을 확인하기 전에는 진동 측정기로
쓰지 않는다. 좌우 진폭·위상·시작 시각은 편집할 수 있지만, 그 설정이 '위에서 아래로
이동하는 촉감'을 만든다고는 적지 않는다 — 그건 사용자가 기록하는 실험 결과다.

파형 표시는 픽셀당 **min/max 쌍**이다. N개마다 한 샘플씩 찍으면 고주파에서 전혀 다른
진폭의 무아레가 그려진다(문서 13.4 와 같은 이유).

## 14.5b 타임라인 드래그와 레이어별 보기 (2026-09-23 추가)

**배치**: 타임라인의 막대를 끌면 시작 시각이, 오른쪽 끝(7 px 안쪽)을 잡아 끌면
지속시간이 바뀐다. 커서 모양이 이동/길이조절로 바뀌고, 끄는 동안 값이 옆에 적힌다.

두 가지를 의도적으로 그렇게 했다.

* **끄는 동안 눈금을 얼린다.** 시간 눈금은 프리셋 길이에 여유를 더한 값인데,
  막대를 늘리면 길이가 늘고 눈금도 같이 늘어난다. 그러면 막대가 커서 아래에서
  달아나 잡을 수가 없다. 그래서 잡은 순간의 눈금을 들고 있다가 놓을 때 푼다.
* **명령은 놓을 때 한 번만 보낸다.** 끄는 동안 매번 보내면 초당 수십 번 렌더를
  시키고, 거절이 하나라도 섞이면 화면과 실제 설정이 어긋난다. 화면은 끄는 동안
  그 자리에서 미리 그리므로 반응이 늦어 보이지 않는다.

값은 보내기 전에 시작 ≥ 0, 길이 ≥ 1 ms, 끝 ≤ 10초로 자른다. 검증기가 어차피
거절하지만, 거절될 것을 보내면 화면이 한 번 튄다.

**레이어별 보기**: 파형 화면에 **합성 / 레이어별 / 선택 레이어** 세 가지가 있다.

* *레이어별* — 레이어마다 자기 줄. 줄을 클릭하면 그 레이어가 선택된다.
  **모든 줄이 같은 세로 배율을 쓴다.** 줄마다 제 최대값에 맞춰 늘리면 조용한
  레이어가 큰 레이어와 똑같이 커 보여서, 무엇이 실제로 센지를 눈으로 비교할 수
  없게 된다 — 그 비교가 이 화면의 용도다. 음소거되거나 다른 레이어의 단독 듣기에
  밀린 줄은 흐리게 그리고 "(안 들림)"이라고 적는다.
* *선택 레이어* — 고른 레이어를 전체 높이로, 합성 전체를 연회색으로 뒤에 깐다.
  혼자만 보면 항상 커 보이기 때문이다.
* 확대 보기도 이 선택을 따라간다.

검증(`drive_gui.py`, 실제 Tk 위젯 26개 항목): 막대 히트 테스트(가운데/끝/빈 곳),
끄는 동안 값이 따라오고 아무것도 보내지 않음, 놓을 때 `layer.set` 한 번, 길이 조절이
시작 시각을 건드리지 않음, 음수·1 ms 미만 차단, 세 보기 모드의 그림이 서로 다름,
레이어 이름과 "(안 들림)" 표시, 줄 클릭 선택, 확대 보기 연동.

## 14.5c 값 막대와 단축키 (2026-09-23 추가)

**모든 파라미터에 막대.** 입력칸 옆에 가느다란 막대가 붙어 끌어서 값을 바꾼다.
막대와 입력칸은 같은 값을 가리키고, 막대는 대충 맞추고 입력칸은 정확히 맞춘다.

* **막대 끝은 그 값이 실제로 가질 수 있는 최대값이다.** 처음에는 "자주 쓰는 구간만"
  훑도록 좁혀 놨다가 되돌렸다 — 끝까지 끌어도 주파수가 500 Hz 에서 멈추는데 실제로는
  2000 Hz 까지 넣을 수 있어서, 막대가 거짓말을 하고 있었다.
* **대신 곡선을 준다.** 1~2000 Hz 를 곧게 펴면 40~300 Hz 가 막대의 2% 안에 눌려
  손으로 맞출 수 없다. 로그로 펴면 60 Hz 가 0.539, 260 Hz 가 0.732 자리에 오고
  2000 Hz 도 여전히 끝에 있다. 0 근처가 중요한 값(시작 시각, 포락선 구간, 감쇠율)은
  세제곱 곡선을 써서 5 ms 가 0.136, 40/s 가 0.271 자리에 온다.

  | 곡선 | 쓰는 곳 |
  |---|---|
  | `lin` | 이미 비율인 값 — 진폭, dB, 0~1 비율, 위상 |
  | `log` | "두 배" 가 의미 있는 값 — 주파수, 지속시간, t0 |
  | `pow3` | 0 근처가 중요한 값 — 시작 시각, 포락선 구간, 감쇠율 |

  그리는 자리(`_ratio_of`)는 잡히는 값(`_value_at`)의 **역함수**다. 둘이 어긋나면
  막대가 가리키는 곳과 클릭해서 나오는 값이 달라진다. 모든 픽셀에서 오차 0 으로 확인.
* 범위 밖 값은 숫자로 넣을 수 있고, 그때 막대는 끝까지 채운 뒤 주황색 표시를 남긴다 —
  **조용히 범위 안으로 끌어당기지 않는다.** 입력한 적 없는 값이 적용되는 일이다.
  지금 그런 경우는 위상 하나뿐이다(막대는 한 바퀴 360도, 검증기는 여유로 3600도).
* 끄는 동안에는 입력칸만 바뀌고 아무것도 보내지 않는다. 놓을 때 한 번 보낸다
  (타임라인 드래그와 같은 이유).
* 그 파형이 쓰지 않는 파라미터의 막대는 잠기고 회색이 된다.
* 오른쪽 패널이 길어져서 스크롤 되는 영역에 넣었다. 창을 줄였을 때 아래쪽 칸이
  잘리면 그 값은 편집할 수 없는 값이 된다.

**단축키**: F1 로 전체 목록을 볼 수 있고, 목록은 소스의 `SHORTCUTS` 하나뿐이라
화면과 어긋날 수 없다.

| | |
|---|---|
| Space / F5 | 재생 |
| Esc | 정지 |
| Ctrl+Shift+X | 전체 출력 해제 |
| Insert / Ctrl+D / **Delete** | 레이어 추가 / 복제 / 삭제 |
| ↑ ↓ | 레이어 선택 이동 |
| M / S | 음소거 / 단독 듣기 |
| Ctrl+N O S E | 새로 / 열기 / 저장 / WAV |
| Ctrl+1 · Ctrl+2 | A 재생 · B 재생 |
| Tab | 파형 보기 전환 |

**입력 중에는 글자 단축키가 동작하지 않는다.** Delete·Space·M·S·화살표는 입력칸
안에서도 뜻이 있는 키다. 그 위에 단축키를 덮으면 이름을 고치다가 레이어가 지워진다.
포커스가 입력 위젯에 있으면 그냥 넘긴다. Ctrl 조합은 입력 중에도 뜻이 같으므로
그대로 둔다.

### 실행하며 잡은 것 두 개

* **막대 끝이 최대값에 닿지 않았다.** `winfo_width()` 가 highlight 테두리까지 세서,
  오른쪽 끝까지 끌어도 한 칸 모자랐다. 테두리를 뺀 폭으로 고쳤다.
* **화살표가 두 칸씩 움직였다.** Tk 는 위젯 → 클래스 → 최상위 순으로 바인딩을
  부른다. 목록에 포커스가 있으면 Listbox 의 클래스 바인딩이 먼저 한 칸 옮기고,
  최상위에 건 단축키가 또 한 칸 옮겼다. 위젯에서 잡고 `"break"` 로 끊었다.

검증(`drive_gui_extra.py`, 실제 Tk 위젯 34개 항목): 18개 파라미터 전부에 막대가
붙음, 값 반영과 레이어 전환 추종, 끄는 동안 안 보내고 놓을 때 보냄, 범위 밖 값
유지와 표시, 잠긴 막대 무반응, 단축키 10종 동작, 입력 중 Delete·Space·M 차단과
Ctrl+D 통과, F1 목록.

막대 매핑은 따로 쟀다: 18개 전부 x=0 에서 최소값, 오른쪽 끝에서 **검증기가 받는
최대값**이 나오고(위상만 의도적으로 360도), 역함수는 모든 픽셀에서 오차 0 이다.

## 14.5d 소리와 같이 재생, 그리고 기본 프리셋 (2026-09-23 추가)

### 소리를 같이 낸다

컨트롤러 내장 스피커로 WAV 를 같이 재생한다. 게임 경로가 이미 쓰는 패링/방어
소리를 들으면서 후보 진동을 만져 볼 수 있다 — 조용한 데서 파형을 판단하는 것은
게임이 실제로 할 일과 다른 것을 판단하는 것이다.

* **햅틱 버퍼에 섞지 않는다.** 스피커와 액추에이터는 다른 트랜스듀서이고 리미터도
  따로 걸린다. 합쳐 버리면 각각의 측정값이 뜻을 잃는다. 같은 큐잉 안에서 **별도
  채널의 별도 voice** 로 나간다.
* **늦추기는 버퍼 앞의 무음이다.** sleep 이나 타이머가 아니다. 레이어와 같은 샘플
  시계 규칙이고, "타격 20 ms 뒤에 소리" 가 두 번 같은 뜻이 되는 유일한 방법이다.
  0 이면 같은 프레임에서 함께 시작한다(같은 두 pump 사이에 큐잉되므로).
* 프리셋에 같이 저장되고 같이 복원된다. 파일이 없으면 그렇다고 기록에 적고 진동만
  불러온다 — 프리셋 전체를 거절할 일은 아니다.
* WAV 내보내기는 여전히 **햅틱 좌/우 한 쌍**이다. 스피커 소리는 이미 디스크에 있는
  파일이고, 3채널로 묶으면 파일이 무엇을 뜻하는지가 흐려진다.

| 패링 (칼 튕김) | 260 ms | 0.974 | 0.128 | deflect_hit.wav |
| 방어 (일반 막기) | 220 ms | 0.985 | 0.197 | block_hit.wav |

**전부 설계 후보다.** 파형이 어떤 모양이어야 할지 생각해서 만든 값이지, 실기에서
재보거나 손으로 확인해 맞춘 것이 아니다. 파일마다 `designStatus:
design_candidate_not_hand_verified` 와 설계 의도를 적은 `note` 가 들어 있다.

설계의 뼈대만 적으면: 패링은 고역이 먼저 죽고 중역 울림이 남도록 레이어마다 감쇠율을
다르게 줬고, 방어는 그 반대로 울림이 없다. 수리검은 의수가 왼팔이라는 **게임 설정을
따라** 왼쪽으로 치우쳐 있다(그렇게 느껴진다고 잰 것이 아니다). 장창은 찌름 → 끌림 →
회수가 시간으로 떨어져 있고, 도끼는 휘두름이 먼저 오고 충돌이 뒤에 온다. 불꽃놀이의
연속 폭발은 타이머가 아니라 레이어 시작 시각이다.

처음 만들었을 때 패링 1.376 / 도끼 1.206 / 예제 B 9.996 로 범위를 넘어 리미터가
물고 있었다. **배포하는 기본값이 처음부터 눌린 채 시작하면 안 되므로** 전부 1.0 아래로
내렸다. 예제 B 는 t 가 t0 에 가까울 때 1/t 가 커지는 것이 원인이라, 진폭을 0.045 로
낮추고 그 이유를 파일의 note 에 적어 뒀다.

파일은 손으로 쓰지 않고 `tools/make_haptic_lab_presets.py` 가 **실제 엔진에 세운 뒤
dump 를 받아** 저장한다. 그래야 앱이 만들어 내는 것과 정확히 같은 형식이고, 만드는
도중에 검증기가 거절하면 바로 드러난다.

검증: 10개 전부 GUI 의 불러오기와 **같은 명령 순서**로 다시 세워, 길이·레이어 수·
모든 수치 필드·수식·소리 설정이 파일과 일치하고, peak ≤ 1.0 에 범위 초과 0,
수식 경고 0 임을 확인했다. GUI 쪽은 목록 채우기, 두 번 클릭 불러오기(자동 재생 안 함),
소리 있는/없는 프리셋의 speaker.load / speaker.clear, 소리 패널 표시를 실제 위젯으로
확인했다.

### 타임라인의 소리 줄 (2026-09-24 추가)

소리를 실으면 **레이어 시간 배치 맨 아래에 그 파형이 자기 줄로** 그려진다. 진동
레이어와 같은 시간축이라, 소리가 타격보다 먼저인지 나중인지, 어디까지 울리는지가
눈으로 보인다.

* **타임라인 눈금이 소리 끝까지 늘어난다.** 패링 큐는 687 ms 인데 프리셋은 260 ms 라,
  프리셋 길이로 눈금을 잡으면 소리의 3분의 1만 보인다. 대신 `preset_length()` 자체는
  건드리지 않는다 — 합성 파형과 분석은 그것을 시간축으로 쓰므로, 거기에 소리를 섞으면
  소리 길이에 따라 그 그림들의 시간축이 흔들린다.
* **제 최대값에 맞춰 늘려 그린다.** 게임 레벨의 큐는 peak 0.116 이라 ±1 기준으로
  그리면 거의 직선이 된다. 여기서 볼 것은 크기가 아니라 시간에 따른 모양이고, 실제
  크기는 옆의 세기 막대와 측정 패널이 말한다. 줄에 그렇게 적어 둔다.
* **끌 수 없다.** 레이어가 아니므로 `timeline_bars` 에 넣지 않았다. 끌 수 있어 보이면
  안 되고, 늦추기는 왼쪽의 막대로 바꾼다. 막대를 끄는 동안 이 줄이 같이 움직이는 것이
  이 그림의 쓸모다.
* 꺼 두면 "소리 (끔)" 으로 적고 흐리게 그린다.

파형 개형은 C++ 이 min/max 버킷 600개로 보낸다(레이어 파형과 같은 형식, 같은 이유).
**프리셋 파일에는 넣지 않는다** — 파일마다 수백 개 숫자가 붙을 이유가 없다.

검증(실제 Tk 위젯 14개 항목): 소리 없을 때 프리셋 길이만 덮음, 실리면 687 ms 까지
덮되 `preset_length()` 는 260 ms 유지, 줄 이름 표시, 끌 수 있는 레이어는 여전히 2개,
소리 줄을 짚어도 레이어가 안 잡힘, 늦추기 200 ms 에 시작·끝·눈금이 함께 이동,
끔 표시, 해제하면 줄이 사라지고 눈금 복귀.

## 14.6 장치와 중복 제어

장치는 목록 번호가 아니라 **Windows 안정 엔드포인트 식별자**로 저장한다. 번호는 다른
장치를 꽂거나 빼면 다른 것을 가리킨다. Windows 기본 출력 장치는 바꾸지 않고, 엔드포인트
볼륨은 앱 내부 gain 과 구분해 자동으로 건드리지 않는다.

라이브 앱(`sekiro_guard_feedback.exe`)이나 `sekiro_trigger_lab.exe` 가 떠 있으면 실험툴이
**거절**한다. 한 컨트롤러에 출력 리포트를 쓰는 주인이 둘이면 서로의 상태를 계속 덮어써서
"가끔 안 먹는" 세션이 되고, 그 원인은 안에서 보이지 않는다. 프로세스 목록을 읽기만 하고
라이브 앱은 건드리지 않는다. `--force` 로 무시할 수 있다. 실험툴 자신도 named mutex 로
한 번에 하나만 뜬다.

트리거는 오디오 라우팅과 **같은** `DualSenseOutputState` 를 통해 나간다. 그래서 트리거
적용이 스피커/출력 경로 바이트를 다시 쓰지 않고, 해제가 액추에이터를 PCM 에서 떼지
않는다. 구현된 네 모드만 제공하고, 각 모드가 실제로 쓰는 값만 입력칸이 열린다 —
안 쓰는 칸이 채워져 있으면 그 값이 적용된 것처럼 보인다.

## 14.7 화면

라이트 모드, 한국어. 밝은 회색 배경 / 흰 작업 영역 / 짙은 글자 / 청록·주황 강조색
두 가지. 상태는 **색과 문구를 함께** 쓴다(색만으로는 색각 이상이 있는 사람에게 정보가
사라진다). 전문용어에는 짧은 한국어 설명을 툴팁으로 붙였다 — 진폭, Hz, 위상, 포락선,
RMS, DC, 리미터, dB, FFT, 창 함수 등.

컨트롤러 그림은 **사각형·원·선으로만 직접 그린 개념도**다. 외부 이미지·아이콘 폰트·
로고·제품 문양을 쓰지 않고, 실제 제품 외곽선도 아니다. 표시하는 것은 이 도구가 실제로
제어하는 경로(L2/R2, 좌우 PCM 채널 번호, 스피커)뿐이다.

## 14.8 저장

`schemaVersion` 이 다르면 **열지 않는다**. 읽히는데 뜻이 다른 파일이 조용히 열리는 쪽이
거절보다 나쁘다. 저장 내용: 모든 레이어의 시간·단위·위상·포락선·gain, 출력 설정
(안정 엔드포인트 식별자, 좌우 채널, 샘플레이트), 분석 조건(FFT 길이·창·시작).

레이어를 잘못 고치면 그 편집을 **되돌리고** 거절한다. 저장해 두었다가 렌더할 때 실패하면
불평이 원인이 된 입력칸에서 멀어지고, 재생할 수 없는 상태가 남는다.
