C:\workspace\sekiro_haptics 프로젝트의 개발을 이어가줘.

현재 사용자 확인으로 패링/일반 방어 이벤트에 맞춰 소리와 진동이 발생한다. Adaptive Trigger는 이 프로젝트의 핵심 기능이다. 이제 개발 순서를 다음과 같이 고정한다.

Adaptive Trigger Runtime → 연속 PCM Mixer → 프리셋 확장 → Event/Preset/Output 통합.

이번 목표는 이 출력 경로를 안정적으로 연결하는 것이다. 날카로운 최초 접촉감, 금속성 질감, 주파수별 체감 보정, 실제 충돌 측정과 FFT/STFT 분석, 진동 A/B/C 튜닝은 후속 과제로 남긴다. 기존 소리의 끊김과 출력 충돌은 이번 런타임 작업에서 해결한다.

먼저 저장소의 AGENTS.md와 관련 문서를 읽고 실제 코드를 확인해라. 아래 지시에서 이미 구현된 부분은 재사용하고, 현재 동작과 부족한 부분을 짧게 정리한 다음 구현에 착수해라. 단계별 빌드와 필요한 테스트를 수행하면서 순서대로 진행해라. 계획 제시만으로 끝내지 마라.

1. 현재 동작을 보존하고 기준을 확보해라.

현재 detector, 이벤트 ID, 주소 해석, 반복 이벤트 인식과 타이밍을 보존해라. 이번 작업을 위해 새로운 게임 신호를 탐색하거나 검증되지 않은 offset을 추가하지 마라.

사용 가능한 실제 capture/replay가 있으면 단발 패링, 일반 방어, 연속 패링의 기존 결과를 회귀 검증에 사용해라. 자료가 없다면 합성 fixture로 출력 경로를 검증하되, 이를 실제 게임 인식 검증이라고 보고하지 마라. 기존 스피커와 진동 기능도 회귀 대상이다.

2. Adaptive Trigger Runtime과 게임 없이 실행하는 Trigger Lab CLI를 구현해라.

기존 USB HID transport를 재사용하고 L2/R2를 독립적으로 제어해라. Off와 Resistance부터 구현·검증하고, 이어 Weapon 형태의 저항 변화와 Vibration을 검증된 프로토콜 범위에서 추가해라. 처음부터 Bow 등 모든 모드를 구현할 필요는 없다.

각 모드가 실제로 지원하는 위치·강도·주파수 등의 필드, 단위, 유효 범위와 인코딩 값을 명확히 해라. 지원하지 않는 파라미터를 모든 모드에 공통 적용하지 마라. HID report의 byte layout과 enable flag는 근거 있는 구현을 확인하고 출처와 버전을 기록해라. 모르는 값을 추측해서 채우지 마라.

트리거, legacy rumble, 스피커 라우팅 등이 각각 별도 HID report를 보내 서로의 상태를 덮어쓰는지 확인해라. HID 출력 상태와 전송을 한 곳에서 관리하고, 한 기능을 바꿀 때 다른 기능의 상태와 필요한 flag가 유지되게 해라. 이미 이런 구조가 있으면 확장해라.

CLI는 장치 선택, L2/R2 선택, 효과와 파라미터 적용, 지속시간, 개별 Off, 전체 Reset을 지원해라. GUI는 만들지 마라. 기존 CLI 확장이 더 적절하면 별도 실행 파일을 만들지 않아도 된다.

효과 수명을 관리해라. 만료·취소·정상 종료·처리 가능한 오류에서 해당 트리거를 Off로 되돌려라. 같은 트리거의 효과 교체 규칙을 정하고, 이전 효과의 만료 처리가 새 효과를 꺼버리지 않게 해라. 재연결 시 중립 상태로 초기화하고 오래된 효과를 자동 재생하지 마라. 연결이 끊긴 장치나 강제 종료 상황에서 물리적 Reset을 보장한다고 보고하지 마라.

L/R 독립 제어, 다른 HID 출력 상태 보존, 효과 교체와 만료, Reset, 재연결 초기화를 mock과 실제 가능한 범위에서 검증해라. 실제 저항이 어떻게 느껴지는지는 사용자 확인 항목으로 분리해라.

3. PCM Mixer를 연속 스트림 구조로 정리해라.

기존 WASAPI 경로와 오디오 로더를 재사용해라. 현재 구현이 이미 연속 스트림과 다중 voice를 지원한다면 다시 만들지 말고 부족한 부분만 수정해라.

장치가 연결되어 출력 세션이 활성화된 동안 스트림을 유지하고, 이벤트마다 독립 재생 위치와 수명을 가진 voice를 추가해라. 이벤트마다 장치를 열고 닫거나 Start/Stop/Reset을 반복하지 마라. 파일 읽기, 디코딩, 무거운 로그와 불필요한 메모리 할당이 렌더링 공급을 막지 않게 해라.

스피커 겹침 정책은 다음을 따른다.
- 정상적인 새 패링/방어 이벤트가 왔다는 이유로 이전 효과음을 중단하거나 fade-out하지 않는다.
- 이전 소리의 잔향 위에 새 소리를 즉시 겹쳐 재생한다.
- 스피커 음원 수명과 햅틱 수명을 분리한다.
- 실제 음원 길이와 반복 간격을 고려한 동시 재생 상한을 둔다. 상한 초과 시에만 오래되고 조용한 voice를 부드럽게 정리하고 그 이유를 기록한다.

스피커와 좌우 햅틱은 논리적으로 분리해 믹싱하고 게인과 리미터도 분리해라. 활성 voice 개수로 전체 신호를 단순히 나누지 마라. 합산 클리핑을 막되 고정 cooldown으로 새 이벤트를 버리지 마라. 기존 EQ와 예술적 파형 튜닝은 이번에 동시에 변경하지 마라.

장치 형식과 채널 매핑은 실제 조사 결과와 기존 설정을 사용해라. endpoint 번호 6이나 특정 채널 용도를 하드코딩하지 마라. Windows 기본 출력 장치와 endpoint 볼륨을 임의로 바꾸지 마라.

기존 legacy rumble 경로를 보존하되 PCM 햅틱과의 모드 충돌을 관리해라. PCM을 못 쓰는 경우의 fallback 조건과 실제 선택된 경로를 명확히 표시해라. 약하게 느껴진다는 이유만으로 PCM 미지원이라고 판단하지 마라.

단발 끝까지 재생, 100/200/400ms 간격 반복, 패링/방어 혼합, Trigger 동시 출력으로 검증해라. 제출 직전 PCM 기록은 선택적으로 제공하고 오디오 공급을 막지 않게 해라. 버퍼 상태와 voice 종료 이유를 기록하되 무음 대기 중 padding이 0인 것을 곧바로 underrun으로 집계하지 마라.

4. 프리셋을 확장하고 기존 이벤트 경로에 통합해라.

기존 구조를 유지해라.
GameSignal → GameEventDetector → GameEvent → EventMapping → HapticPreset → Runtime → Backend.

프리셋은 필요한 PCM 햅틱, L2/R2 Trigger, 기존 Speaker 출력을 함께 표현할 수 있게 확장해라. 각 출력의 시작 시점과 수명은 독립적으로 정의하고, 기존 legacy 프리셋과 설정을 계속 읽을 수 있게 해라. 신규 필드의 단위·기본값·버전 처리를 문서화하고 잘못된 설정은 출력 전에 거부해라.

Detector 내부에서 HID/WASAPI를 직접 호출하지 마라. 출력에 필요한 공통 기준 시각을 전달하되 HID와 오디오의 전송 방식 차이를 반영해라. Trigger 효과의 충돌 처리는 PCM 파형 합산과 별개로 관리해라.

실제 패링과 일반 방어는 기존 매핑과 현재 음원·파형으로 연결해라. Adaptive Trigger 통합은 수동 이벤트 또는 Replay의 별도 데모 프리셋으로 확인할 수 있게 해라. L1 패링에 L2/R2 저항을 기본으로 연결하거나 게임 버튼을 자동 재매핑하지 마라. 검증되지 않은 의수·갈고리 이벤트를 감지되는 것처럼 추가하지 마라.

이벤트별 correlation ID와 단조 시각으로 감지, 매핑, 스케줄링, PCM 렌더 반영, HID 제출을 연결해 추적할 수 있게 해라. 실제 기록 가능한 단계만 보고하고, API 제출 시각을 물리적인 소리·진동 시작 시각으로 해석하지 마라.

5. 완료 조건과 보고 방식.

정상적인 연속 이벤트에서 누락·중복 없이 예상 출력이 생성되고 이전 스피커 잔향이 유지되어야 한다. 이벤트 수와 voice 수는 프리셋의 출력·레이어 수를 고려해 비교해라. 트리거 변경이 스피커/PCM 상태를 깨뜨리지 않고, 종료·재연결 시 이전 효과가 다시 살아나지 않아야 한다.

수정 이유, 확인한 코드 근거, 실제 실행한 빌드/테스트, 미실행 항목, 사용자 체감 확인 항목을 구분해 보고해라. 실행하지 않은 하드웨어 검증을 통과했다고 쓰지 마라.

사용자가 따라 할 검증 명령을 실제 생성된 실행 파일과 옵션 기준으로 안내해라. 순서는 Trigger 단독 → PCM/스피커 단독 → 동시 출력 → 기존 Sekiro 패링/방어 연결이다.

하드웨어 체감 확인이 남더라도 가능한 구현과 자동 검증은 먼저 마쳐라. 확인이 필요한 지점에서는 짧은 비교 절차와 관찰할 결과를 제시해라.

이번 범위 이후의 로드맵은 EffectLab → Sekiro UX 및 날카로운 접촉·금속성 튜닝 → 배포 준비 → 다른 게임 → Haptic Studio로 기록해라. 이번 변경에는 GUI, 실제 충돌 측정, 다른 게임 지원, 자동 배포를 포함하지 마라.
