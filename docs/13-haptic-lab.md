# 13. Haptic Lab — 게임 없이 PCM 진동 비교하기 (2026-09-23)

프리셋을 만지기 전에, **장치가 무엇을 하는지** 손으로 확인하는 작은 벤치.

```
python tools/haptic_lab_gui.py          # 저장소 루트에서
```

## 13.1 두 조각으로 나눈 이유

| | |
|---|---|
| `apps/haptic_lab/main.cpp` → `sekiro_haptic_lab.exe` | 출력. 오디오 엔드포인트를 **한 번** 열고 렌더 스레드를 **한 번** 띄운 뒤, stdin에서 한 줄씩 명령을 받고 stdout으로 JSON 한 줄씩 답한다 |
| `tools/haptic_lab_gui.py` | Tkinter 화면. 오디오를 전혀 소유하지 않는다 |

기존 믹서·엔드포인트 선택·검증된 햅틱 채널을 **그대로** 재사용한다. 다시 구현했다면
게임이 실제로 내보낼 것이 아니라 도구 자신을 측정하게 된다. 웹 서버도, 큰 UI
프레임워크도 없다.

**이 파일이 지키는 한 가지 규칙**: 파라미터 변경이 장치를 다시 열거나 스트림을
Reset하지 않는다. 재개방은 수십 ms의 불연속과 새 리미터 상태를 뜻하고, 그건 방금 바꾼
파형 탓으로 오해되기 딱 좋은 종류의 인공물이다. 스트림은 시작 때 열려 프로세스가 끝날
때까지 유지되고, 모든 명령은 **거기에 무엇을 queue할지**만 바꾼다.

## 13.2 첫 버전이 하는 것

사인파 하나. 주파수 20–500 Hz, 진폭 0–1, 길이 20–1000 ms, 시작/종료 페이드,
좌/우 채널 세기(독립된 두 값이지 balance가 아니다). 단발, 간격 지정 반복, 정지 버튼과
**Esc**. A/B 슬롯 저장·불러오기·번갈아 재생. 48 kHz 스테레오 float32 WAV + 설정 JSON
내보내기. 시간축 파형 표시.

시작할 때 **자동 재생하지 않는다**. 정지·창 닫기·프로세스 종료 시 8 ms 페이드로 내리고
(끊으면 그게 틱이다) 큐를 비운 뒤 HID를 중립으로 되돌린다.

## 13.3 보간 — 무엇을 하고 무엇을 안 하는지

반복 재생 중 슬라이더를 끌면:

* **진폭과 좌/우 세기**는 약 120 ms 시상수로 목표를 향해 접근한다. 버스트 사이에서
  레벨이 계단으로 튀면 사람은 그걸 파형의 성질로 읽는다.
* **주파수·길이·페이드**는 버스트의 *모양*을 정의하므로 다음 버스트에 통째로 적용된다.
  이미 생성된 사이클 중간에 보간할 것이 없다.
* **단발 재생은 보간하지 않는다.** 화면에 있는 값을 그대로 낸다.

## 13.4 숫자 — 샘플 값이지 진동이 아니다

`Measure` 버튼은 한 번의 버스트를 WASAPI로 넘어가는 길목에서 캡처해, **생성 직후**와
**실제 제출**을 같은 함수로 잰다. 리미터 감쇠량과 클리핑 샘플 수도 같이 나온다.
중간에서 약해졌는지가 인상이 아니라 비교가 된다.

두 가지를 정확히 해 둔다.

1. **캡처는 버스트에 정렬한 뒤 잰다.** 캡처 창은 일부러 버스트보다 길어서 앞뒤에 무음이
   있다. 그 창 전체로 RMS를 내면 패딩까지 나눠서 생성값보다 한참 낮게 나오고, 그건
   "장치가 약하게 만들었다"는 정반대 결론이 된다. 실측: 정렬 전 0.244 / 정렬 후 0.345
   (생성값 0.345와 일치).
2. **이건 진동 측정이 아니다.** 40 Hz와 300 Hz는 같은 진폭이면 전선 위에서 같은 숫자지
   손에서 같은 느낌이 아니다. 등청감 보정도, 주파수별 트림도, 정규화도 **일부러** 없다.
   장치가 무엇을 하는지 알아내는 도구가 그걸 몰래 보정하면 안 된다.

파형 표시는 픽셀당 **min/max 쌍**이다. N개마다 한 샘플씩 찍는 흔한 방식은 여기서
틀린다 — 500 Hz를 1000 ms 그리면 500 사이클이 몇백 픽셀에 들어가고, 한 샘플씩 뽑으면
전혀 다른 진폭의 느린 무아레가 그려진다. min/max는 그럴 수 없다. 버킷이 한 샘플이면
둘이 같아져 정확한 파형이 된다.

## 13.5 검증 (실행한 것)

* 단위 테스트 774/774, ctest 4/4. `test_tone_burst.cpp` 10개는 생성기가 조용히
  정규화·클램프·페이드로 진폭을 먹지 않는지를 본다.
* 명령 통로 왕복: ready / set / 범위 밖 거부 / wave / play / measure / repeat +
  중간 파라미터 변경 / stop / export.
* 투명성: 진폭 0.5에서 생성 = 제출 (peak 0.5, rms 0.345, 리미터 0 프레임).
* 손실이 있을 때 보이는가: 진폭 1.0 / 45 Hz / 400 ms에서 생성 peak 1.0 rms 0.707 →
  제출 peak 0.976 rms 0.677, 리미터 63880 프레임 / -0.40 dB, 클리핑 0.
* 내보낸 WAV: formatTag 3 (IEEE float), 2 ch, 48000 Hz, 32 bit, peak 0.5.
* `guard_feedback --play alternate` 회귀 통과 — 이 작업은 게임 경로를 건드리지 않았다.

**손맛은 확인하지 않았다.** 위는 전부 샘플 값이다.

## 13.6 이번에 하지 않은 것

게임 감지, 복합 파형 편집, FFT 화면. 레거시 럼블 대체도 하지 않는다 —
`MarkPcmHapticsActive`는 장부 기록일 뿐 `HAPTICS_SELECT`를 세우지 않으므로 액추에이터는
PCM 경로에 남는다.
